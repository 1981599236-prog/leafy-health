# food_ai 云函数

这个函数让网页安全调用任意 **OpenAI 兼容的视觉模型接口**。网页只提交照片和模型设置；真正的 API Key 会在函数内加密保存，识别时也只在函数里解密使用。

## 首次部署前

1. 在 CloudBase 文档型数据库创建集合：`health_ai_configs`。
2. 集合权限选择“仅管理员可读写”。网页不会直接读取此集合。
3. 在 CloudBase 云函数页面创建函数：名称为 `food_ai`，运行环境选 Node.js 20。
4. 上传本文件夹中的代码，并勾选“安装依赖”。入口文件为 `index.main`，超时建议设为 60 秒。
5. 在函数的环境变量中添加 `AI_CONFIG_ENCRYPTION_KEY`。值可以是你自己创建的一串至少 20 位的随机文字（建议用密码管理器生成）。它用于加密你在 App 页面填入的模型 API Key；不要提交到 GitHub，也不要在以后随意更换，否则已保存的 API Key 将无法读取。
6. 在云函数的权限控制中，只允许已登录用户调用 `food_ai`。

部署完成后，回到 App 的“我的 → AI 识别模型”填写服务商名称、API 链接、模型名称和 API Key。

## 饮食识别的可靠性机制

每次识别时，网页会先把照片压缩后临时上传，取得短时访问链接交给云函数。云函数完成识别后，网页会立即删除这张临时图片；`health_food` 中只保存食物名称、份量、热量、营养数据、可信度和用户主动填写的文字说明，不保存原始照片。

识别流程分为三层：

1. 模型按保守规则列出照片中清楚可见的食物与估算份量。
2. 函数检查“各食物热量之和”和“三大营养素换算热量”是否出现明显矛盾。
3. 当照片不清楚、混合餐食较复杂、用户提示仍不足，或发现数值冲突时，才会额外调用一次同一模型复核。清楚的照片只做一次识别，避免无意义地增加调用量。

App 中的“补充说明”是可选的，例如“半碗、少油、没有喝汤”。它用于补足照片无法表达的份量或做法，不会要求用户每次填写。

## 接口兼容范围

第一版支持 OpenAI 兼容的视觉接口：函数会向 `API 链接/chat/completions` 发送图片。若你填写的链接本身已以 `/chat/completions` 结尾，不会重复追加路径。

不同服务商对多模态消息格式可能有差异。若某个模型不兼容，把它的官方 API 文档链接发给我；我会为它增加专用适配器，不会影响你已保存的其它模型配置。
